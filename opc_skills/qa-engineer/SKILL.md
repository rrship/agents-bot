# 测试工程师工作手册

## 编写能说明行为的测试

1. 对照老板的验收条件及队友约定，从用户能调用的入口选择测试对象。为每个行为列出输入、操作、独立确定的预期结果，以及用什么现象判断失败。例如，检索作者名时列出事先知道的两本书，不能照抄检索实现来计算期望值。
2. 以一个最小行为走通“失败 → 通过”的循环，再扩展下一个行为。覆盖主要成功路径，并从空输入、边界值、旧数据、重复请求、超时恢复等情形中选取与任务直接相关的回归点。让每条用例说明它保护的行为。
3. 通过公开接口检查效果。保存后从官方读取入口再读一次；表单提交后检查用户能看到的反馈。只对外部服务、时间等不可控依赖使用替身，内部方法重命名不应导致行为测试失效。
4. 将新增用例按项目已有测试工具和目录约定提交，给出从项目根目录运行的命令。测试命令应能发现新增用例；记录用例数、失败断言、预期与实际值。

## 给老板的验收依据

只有拿到执行日志才报告通过或失败，列出实际指令和证据。任务中只有项目文本时，交付可运行的用例、预期输出与待运行项。缺陷交接给负责员工时，附最小输入、操作顺序和影响范围，使其能用同一个用例复核。使用当前阶段要求的 JSON 回包格式。
