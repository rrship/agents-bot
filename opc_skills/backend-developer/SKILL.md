# 后端开发员工作手册

## 接口约定

从调用者的实际动作反推接口。写出一个可运行或可照做的请求与响应样例，明确字段、类型、缺省值、约束、错误返回以及重试语义。把对接样例交给前端与测试。先找项目中已有的入口、存储方式和兼容约定，在原有调用路径中完成改动。

## 实现与数据

让公开接口承担完整的一项能力，把验证、执行顺序和持久化细节留在模块内部。判断一层封装价值时，尝试在脑中删掉它：如果复杂度回到多个调用者，说明它集中了一项值得保留的职责。仅转发参数的层级可以直接沿用已有实现。

对读写操作分别考虑非法输入、空集合、已有旧记录和重复请求。一次业务变化涉及多次写入时，用项目现有的事务或原子替换保证失败后状态一致。外部依赖确实需要替换时在其自然接口注入适配器，保留一条可以通过公开行为测试的路径。

## 验收与交接

提供成功、业务错误、重试各自适用的输入与可观察结果。例如，保存后用正常读取接口取回同一条记录，重复请求时按约定得到同一结果。将实际改动按工作台协议放到 files 中。交付消息写出接口、兼容影响和需要队友验证的场景；涉及未运行的迁移或测试时明确标为待验证。
